# Building and testing

## Toolchain

There is no `cargo` on the host: run it through the flake's dev shell, `nix develop -c <cmd>`
from the worktree. The shell has rustc, clippy, rustfmt, `cargo tauri`, Node, pnpm and
WebKitGTK, and sets `CARGO_BUILD_JOBS=4` unless you set it (a build at every core's worth runs a
shared machine out of memory; exit code 137 means that happened). Rust 2024, resolver 3,
default rustfmt and clippy settings.

## What CI runs

`.github/workflows/ci.yml`; `scripts/check.sh` runs the same here (`--help` for its flags):

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets --locked -- -D warnings` (warnings are errors)
- `cargo test --workspace --locked`, on Linux and Windows. It includes `bindings_are_up_to_date`
  and `no_field_reaches_the_ui_as_null_unless_it_is_an_option` in `crates/app/src/app.rs`.
- The desktop UI (`crates/app/ui`): `pnpm install --frozen-lockfile`, `pnpm typecheck`,
  `pnpm test`, `pnpm build`, `pnpm build:mock`.
- The Nix package, only when a pull request changes what Nix builds with (the flake, `nix/`,
  manifests, lockfiles, `build.rs`, `tauri.conf.json`, the UI's lockfile, `assets/`,
  `packaging/`): `nix flake check --no-build`, then `nix build .#keefast .#keefast-agent`.
- The Plugins (`plugins/card`, `plugins/template`) in `nix develop .#plugins`, and the
  Companion extension (`extension/`).

## The inner loop

- Test one crate at a time: `nix develop -c cargo test -p keefast-core` (or
  `keefast-workspace`, `keefast-agent`, `keefast-native-host`, `keefast-plugins`). One test file:
  `cargo test -p keefast-workspace --test browser_fill`.
- Avoid `-p keefast` (the Tauri app) unless you change it: it builds Tauri and WebKitGTK's
  bindings. `--workspace` builds it too.
- Each worktree's `target/` grows to 20 GB or more. Delete it when you are done, or point
  `CARGO_TARGET_DIR` at another worktree's idle one. Avoid `--release`.
- Key derivation is slow in debug, so `[profile.dev.package]` in `Cargo.toml` optimises the
  crypto crates, and the fixtures use cheap KDF settings. Tests that create Vaults should too,
  as the crates' `tests/support` helpers do.
- Opt-in: `crates/workspace/tests/dropbox_live.rs` (`--ignored`, needs a Dropbox app key).
  A fake Dropbox for manual runs: `cargo run -p keefast-workspace --example fake_dropbox`.

## Generated bindings

`crates/app/ui/src/bindings.ts` is generated by tauri-specta from the commands, DTOs and events
registered in `specta_builder()` (`crates/app/src/app.rs`). After changing any of them, run
`pnpm bindings` in `crates/app/ui` and commit the file; `pnpm bindings:check` fails when it is
stale. Both build the `keefast` crate. The pre-commit hook (`.githooks/pre-commit`, enabled by
`scripts/setup-worktree.sh`) runs the check when those files change.

DTOs must not hold `f64`/`f32` outside an `Option`, or `u64`/`i64` at all: specta exports
floats as `number | null` and refuses 64-bit integers. Use `u32`. A test fails on a float field
(`crates/app/ui/README.md`, "Adding or changing a command").

## The UI without Rust

`scripts/ui-mock.sh start` serves the UI over its mock backend on this worktree's own port
(`.t3/ui-mock-port`), and `scripts/ui-mock.sh stop` stops it by its process ID. Don't
`pkill -f "vite --mode mock"`: it matches your own shell and other worktrees' servers. The mock
is described in `crates/app/ui/README.md`.
