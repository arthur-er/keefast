# Storage providers live in the `workspace` crate, not a `storage` crate of their own

The PRD (#2) planned a `storage` crate for the Storage provider interface, its local and Dropbox implementations, and the Local cache. They live in `keefast-workspace` instead, as modules (`storage`, `atomic_file`, `dropbox`, `cache`), behind the same `StorageProvider` trait the Workspace is given, so tests still inject fake storage and a fake Local cache. The Workspace is their only user: the app reaches storage only through it, and the native host never touches a Vault file. They also share what the Workspace already owns: atomic writes with the app config and Attachments, the OS secret store for Dropbox's tokens, and Dropbox's errors, which become each Vault's Sync status. A separate crate would have had one dependent, needed those shared parts split out with it, and bought nothing in build times or boundaries that the trait doesn't give already. `core` stays free of I/O either way. If something besides the Workspace needs a Storage provider, such as a command-line tool, the modules can move into a crate of their own then, without changing the trait.
