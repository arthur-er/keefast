# Icons in sign-in fields, and the command palette over the page

The Companion extension can show keefast's icon in sign-in fields, as KeePassXC-Browser does. That needs a script in every page as it loads, which reverses "nothing runs until you ask", so it is opt-in: `<all_urls>` is an optional host permission, asked for when the user turns the icons on in the popup, and the script is registered at runtime only while it is granted. Without it the extension stays `activeTab`-only and installs without the "read and change all your data" warning. The icons show nothing secret and ask keefast nothing until clicked, so visiting a site never tells keefast about it or prompts there. Pages' scripts get no access to the extension's storage, where Pairings live.

Clicking an icon with no single Entry for the site opens a command palette over the page. It is an extension page in a frame, in a closed shadow root, opened with a one-time token, so the page can neither read what it lists nor drive it. Typing searches every Vault paired with the browser, through keefast's own protocol messages `keefast-search-entries` and `keefast-pick-entry` (ADR 0003), which never return passwords in search results. A Vault whose Default access policy is to deny is not searched, and Entries denied the site are left out. Picking an Entry there is the user's Access decision: keefast gives it to the site without asking again, remembers it as allowed for the site, and, if the user chose so in the extension, adds the site to the Entry's URLs (`KP2A_URL…`, as KeePassXC stores them). We accept that a user can give a site another site's Entry in one step, since they picked it by name. We did not want a second confirmation in keefast for something the user just chose. Hiding the icons on a site is a machine-local preference in the extension, not Vault data (unlike ADR 0005).
