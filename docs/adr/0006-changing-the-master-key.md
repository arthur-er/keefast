# Changing the master key: keep the old key only until the change is saved

Changing a Vault's master key (or its cipher or key derivation) is an edit like any other: the Vault file gets it when the Vault is next saved, and a save Merges in changes made elsewhere before writing. Until the new key is saved, the Vault keeps the key its Vault file has, so the save can still open a version another device wrote with it and Merge it. Once the save has gone through, the old key is zeroized and forgotten (ADR 0004).

The consequence is that a version of the Vault file written later with the old key — another device that hasn't seen the change yet, and saves over it through a sync tool — can no longer be opened, so it can't be Merged. keefast then refuses to save rather than overwrite it: the save fails and the Vault stays unsaved. The user resolves it by changing the key on the other device as well, or by changing the key back here. We prefer this to keeping old keys around indefinitely, which would leave key material in memory for as long as the Vault is open, and to overwriting the other version, which would lose its changes.
