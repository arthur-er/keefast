# Filling payment forms from a Card, and the frames they sit in

The Companion extension fills payment forms from an Entry's Card, with a Plugin capability, `browserFill`, that ADR 0009 listed for later. A Plugin's manifest names the kind of form a facet fills (`payment`, for now the only one) and the HTML `autocomplete` token each of its Owned fields goes into (`cc-number`, `cc-name`, `cc-exp`, `cc-exp-month`, `cc-exp-year`, `cc-csc`). The user agrees to the fields by name when installing it, and an update filling one more field asks again. keefast hands the browser protocol only these names: it never runs a Plugin to fill.

Two protocol extensions (ADR 0003) serve it, beside the command palette's own (ADR 0007). `keefast-search-entries` takes a `form`, and then finds only Entries with data for that form; an empty query lists them all, up to the palette's twenty, since a Vault holds few and the palette shows only their names. `keefast-fill-form` gives the Entry the user picked its values, protected ones included, by token. Access decisions and the Default access policy work as they do for a pick in the palette: a Vault whose policy is to deny isn't searched, an Entry denied any of the hosts the values go to can't be picked, and picking is the Access decision, remembered as allowed. A Card isn't added to the site's URLs: it isn't the site's. Existing messages are unchanged, so KeePassXC-Browser keeps working.

The extension never fills a Card without the user picking it in the palette. keefast's icon in a payment field, and the shortcut on a payment form, open the palette even when there is one Card. A value goes only into a field the user can see. The CVV goes only into a field the page marked `cc-csc`. Other fields are found by their `autocomplete` tokens first, then by their names and labels. keefast's icon shows in a field it guessed only beside a card number field; once the user has picked a Card, guessed fields are filled without one too, since the number may be in a payment provider's frame.

Payment fields often sit in a frame from the payment provider. With the icons on (ADR 0007), the extension shows its icon in frames too, but only in their payment fields. Values go to the page's own origin and to the origin of the frame the user clicked the icon in. The palette names that origin when it isn't the page's ("in a frame from js.stripe.com"), and keefast remembers the Access decision for its host too. A frame from any other origin gets nothing, and each frame gets only the values its fields take, so the CVV goes only to a frame with a `cc-csc` field. We accept that a page's own frames and the frame the user chose share the values, since the user picked the Card seeing both names. Without the icons, the extension can read only the page itself, so it fills only the page's own fields.
